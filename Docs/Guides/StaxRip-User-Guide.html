Portable video workflow, explained

From source file to a controlled encode.

StaxRip is a transparent front end for frame servers, encoders, muxers, and media tools. It rewards a deliberate workflow: inspect, configure, preview, queue, then verify.

Windows x64 onlyAviSynth+ & VapourSynth includedNo installerLogs every tool step
01 / Orientation

Start here

StaxRip is not a one-click transcoder. It is a project workspace that generates scripts and command lines, runs external tools, and leaves enough evidence for you to understand what happened.

1

Inspect the source

Confirm resolution, frame rate, color format, audio tracks, subtitles, and duration.

2

Choose the processing path

Select a template and decide whether AviSynth+ or VapourSynth best matches the filters you need.

3

Preview before queuing

Check crop, resize, script output, encoder settings, audio, and container compatibility.

The safest mental modelStaxRip orchestrates other programs. A successful StaxRip setup therefore depends on the selected source filter, plugins, encoder, muxer, hardware, and runtime files—not only on StaxRip.exe.
02 / Setup

Install the portable package

Download x64 archive
Verify source
Extract with 7-Zip
Use writable folder
Launch StaxRip.exe
Choose settings
Run a test
  • Use a 64-bit edition of Windows. Current StaxRip does not support 32-bit Windows or 32-bit builds.
  • Extract the entire archive; do not run the executable from inside the archive viewer.
  • Choose a folder your account can write to, such as D:\Tools\StaxRip-v2.52.5. Protected system folders can break tools that write beside themselves.
  • Keep the bundled Apps, Fonts, and Icons trees with the executable.
  • AviSynth+, VapourSynth, and Python are included in the portable package; system-wide installs are not required for the normal bundled path.
  • Install current Microsoft Visual C++ runtimes and keep GPU drivers current if you plan to use hardware encoders.
Windows 7 is only partially usableModern bundled tools and Python/VapourSynth combinations have moved beyond Windows 7. Treat downgrade workarounds as unsupported expert maintenance, not a normal setup.

03 / First launch

Handle the first-run dialogs

Settings directory

The portable/instance-local option is easiest to back up and lets multiple StaxRip versions coexist. A shared settings location is convenient, but can expose old templates or serialized state to a newer version.

Long path support

Enable it when prompted unless organizational policy says otherwise. Media workflows easily exceed legacy path limits through long source names and temporary subfolders.

What's New is modal

After an update, the changelog appears in a separate StaxRip window and blocks the main interface. Scroll if desired, then click the OK button at the bottom-right. If the main window looks unresponsive immediately after an update, check for this window first.

Verified behaviorOn v2.52.5, dismissing the changelog exposes the normal Automatic Workflow main window. The acknowledgement is saved so the same version does not need to show it every time.

05 / Guided workflow

Your first controlled encode

1

Load a template

Start with Automatic Workflow or a known template before opening the source.

2

Open one source

Use File → Open Video Source File(s). Let indexing or demux steps finish.

3

Confirm detection

Check frame rate, scan type, bit depth, color layout, audio, and subtitles.

4

Set picture operations

Crop only unwanted borders. Resize only when your delivery target requires it.

5

Choose output

Select encoder, quality/rate control, container, target path, and audio profiles.

6

Preview and sample

Inspect the generated script and encode a short representative section first.

7

Add the job, then start it from Jobs

Adding a job snapshots the project into the queue. Open Tools → Jobs, verify ordering and activation, then start processing. Read the final log and inspect the produced file.

Never use irreplaceable media as the only copyStaxRip creates temporary data and output files and can run commands or custom events. Keep source backups and write outputs to a deliberate destination.
06 / Script engine

AviSynth+ or VapourSynth?

Common failureMissing/incompatible plugin or source filterPython/plugin/API mismatch or incomplete color metadata
  • Do not choose a backend only because it sounds newer; choose the chain you can preview and reproduce.
  • Filter order is executable order. Move one filter at a time and preview after structural changes.
  • Use Preview Code, Script Info, and Advanced Script Info when a frame-server error is vague.
  • A third-party plugin is executable native code. Obtain it from a trusted source and match x64 plus the expected API/runtime.
07 / Picture

Crop, resize, and preview

Crop

Remove real borders, not picture content. Check several scenes because letterboxing can change. Dolby Vision and variable framing deserve extra attention.

Resize

Keep aspect-ratio error near zero. Respect the encoder's dimension modulus, chroma subsampling, and delivery requirements.

Preview is your visual contractInspect the start, a dark scene, a bright scene, motion, credits, subtitles, and the end. A valid script is not automatically a good result.

The target panel describes frames before the encoder. Encoder-side scaling, pixel-format conversion, metadata, and muxer behavior can still change the final file.

08 / Delivery

Encoder, rate control, and container

DecisionPractical rule
Software vs hardwareSoftware encoders often maximize efficiency; hardware encoders prioritize speed and depend on supported GPU generation/drivers.
Quality vs sizeUse a quality mode when size can vary. Use bitrate/size targeting only when the delivery limit is real.
MKV vs MP4Choose based on player compatibility and the audio, subtitle, chapter, attachment, and codec features you need.
PresetSlower usually trades time for compression efficiency, not a guaranteed visible improvement.
MetadataVerify HDR/Dolby Vision, color range/primaries/transfer, aspect ratio, language, default, and forced flags in the final file.
Test the actual playback chainA technically valid encode may still fail on a television, browser, phone, editor, or hardware decoder. Use a short sample before committing hours.
09 / Streams

Audio, subtitles, chapters, attachments

  • Identify tracks by content, language, channel layout, title, and commentary status—not only by stream number.
  • Copy/Mux preserves a compatible encoded stream. Re-encode only for compatibility, size, channel layout, or processing needs.
  • Set language, title, default, forced, commentary, and hearing-impaired flags deliberately.
  • Use No Audio for a track you explicitly do not want in the output.
  • Confirm the chosen container supports every selected codec and stream feature.
  • After muxing, inspect the final file with MediaInfo and test track switching plus subtitle behavior.
10 / Execution

Assistant, queue, logs, and recovery

Assistant

Resolve red errors. Read warnings instead of accepting them reflexively; most messages lead to the responsible control.

Jobs

Adding a job is not the same as starting it. Confirm order, active state, target uniqueness, and available disk space.

Logs

The log shows generated commands and child-tool output. The first concrete error is usually more useful than the final cascade.

A job failed. What should I save?
Save the StaxRip version, project/template identity, source facts without private filenames if needed, the first failing command, the first error block, exit code, and whether the same step reproduces. Logs can contain local paths and media names; review them before posting publicly.
Can I run jobs in parallel?
StaxRip supports parallel child processes, but storage bandwidth, memory, GPU sessions, and tool thread counts can make more parallelism slower or unstable. Establish one reliable job before increasing concurrency.
11 / Maintenance

Update without losing a known-good setup

  1. Finish or pause important jobs and back up the settings directory, templates, profiles, events, and custom scripts.
  2. Extract the new portable release into a new folder instead of overwriting the only working copy.
  3. Launch it, choose the intended settings location, and close the modal What's New window with its bottom-right OK button.
  4. Open a known source, preview the script, and run a short encode using the tools/plugins you depend on.
  5. Keep the previous folder until the new version has completed a representative real job.
Settings compatibility deserves a backupProjects and settings are active program state, not plain preferences. Sharing them across versions is convenient but makes rollback harder if a format or default changes.
12 / Diagnosis

Troubleshoot from the first broken boundary

The main interface looks blocked after an update
Look for the separate StaxRip v… What's New window. Scroll to or locate the bottom-right OK button. It is modal and intentionally blocks the main form.
StaxRip does not start
Confirm Windows x64, a complete extraction, a writable folder, .NET/Visual C++ runtimes, and that antivirus did not quarantine bundled DLLs. Try a new settings directory before deleting existing settings.
A source will not open
Check MediaInfo, source-filter choice, indexing output, available disk space, path length, and whether the format needs a different source plugin. Try a short simple local path to separate path issues from decoding.
The script errors
Use Script Info and Preview Code. Identify the first missing namespace, filter, DLL, Python module, or color-conversion error. Verify x64 plugin/API compatibility and required color matrix/range arguments.
A hardware encoder is missing or fails
Update the GPU driver, confirm the GPU supports the requested codec/profile/bit depth, and inspect the encoder's own output. Test a software encoder to separate project problems from hardware capability.
The output has the wrong crop, size, timing, or streams
Compare source and target panels, Preview, generated script, encoder command, and final MediaInfo. For VFR sources, avoid assuming one constant frame rate. For streams, verify muxer flags and not just the selected profile label.
Closing asks “Save changed project?”
This is expected after a source or project option changes. Choose Save to retain the project, Don't Save to discard the current changes, or Cancel to return to StaxRip.
13 / Advanced use

Templates, commands, scripts, and automation

Templates capture repeatable project choices. Prefer several focused templates—delivery, archival, hardware-fast, animation—over one template with many hidden assumptions. Save a template before loading a source.

StaxRip also exposes command-line commands, event commands, custom menus, macros, and PowerShell scripts. These can read/write files and start programs with your Windows account's authority. Review scripts before placing them in an auto-loaded settings folder.

StaxRip.exe -LoadTemplate:"Automatic Workflow" -SetHideDialogsOption:true "D:\Media\source.mkv"
Argument order mattersLoad the template before changing project options such as -SetHideDialogsOption:true. Otherwise template loading can correctly ask whether to save the modified current project.

14 / Reference

Compact glossary

Frame serverAviSynth+ or VapourSynth evaluates source/filter scripts and supplies frames to the encoder.
Source filterThe first script operation that indexes/decodes the input into frames.
EncoderCompresses video or audio; examples include x264, x265, SVT-AV1, NVEncC, and FFmpeg-based paths.
Muxer/containerCombines encoded video, audio, subtitles, chapters, and metadata into MKV, MP4, or another container.
CFR / VFRConstant or variable frame rate. VFR preserves varying frame durations and requires timing-aware handling.
DAR / SAR / PARDisplay, storage, and pixel aspect ratios used to describe intended and stored geometry.
TemplateReusable project defaults. A project is a source-bound working state; a job is a queued snapshot for processing.
Guide boundaryThis guide describes safe general operation for the v2.52.5-era interface. Exact encoder options, plugin availability, and hardware capability change frequently. Use the bundled tool output and current StaxRip documentation as the final authority for a specific job.
